# Artef M0–M5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build artef — self-hostable service for storing/serving agent-generated HTML with SSO, per-document ACL, live updates, plus the Rust CLI — through milestone M5 of `artef-spec.md`.

**Architecture:** Single TypeScript server (Hono + Drizzle + Postgres 16) serving API, auth, viewer shell, and sandboxed content on ONE origin; untrusted HTML is neutralized by a CSP `sandbox` response header and a short-lived HMAC content token (spec §2). Rust CLI (`clap`) does lint/push/watch with hash-first uploads. Live updates fan out via Postgres LISTEN/NOTIFY → SSE.

**Tech Stack:** Node ≥22, TypeScript (strict), Hono ^4, @hono/node-server ^1, drizzle-orm + drizzle-kit, pg ^8, openid-client ^6, vitest ^3, tsx; Rust: clap 4, tokio 1, reqwest 0.12 (rustls), lol_html 2, flate2, sha2, serde, toml, tiny_http, webbrowser; tests: wiremock 0.6, tempfile.

**THE SPEC IS LAW:** `/Users/adarsh/adarshroy/artef/artef-spec.md`. Every task references its sections. Read the referenced sections before implementing. Where this plan and the spec conflict, the spec wins — flag the conflict in your report.

## Global Constraints

- Repo root: `/Users/adarsh/adarshroy/artef`. Work on `main` directly (greenfield repo).
- The CSP sandbox token list on `/c/:id` responses must NEVER contain `allow-same-origin` (spec §2.1–2.2). This is the product's core invariant.
- Three routes serve user-supplied bytes; each carries its exact header set from spec §2.2. Nothing else may serve user bytes.
- Env var names come verbatim from spec §10: `URL`, `SECRET_KEY`, `DATABASE_URL`, `MAX_ARTIFACT_BYTES` (default 10485760), `MAX_VERSIONS` (default 20), `LINK_PREVIEW` (default `name`), `ALLOWED_DOMAINS`, `ADMIN_EMAILS`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_DISPLAY_NAME`, `WORKSPACE_DOMAIN_MAP`, `FORCE_HTTPS`, `PORT`.
- Machine tokens are `art_live_` + 43 base64url chars; only `sha256(token)` is stored (spec §5.6).
- Blobs are gzipped at the application layer; the server never decompresses on the serve path unless the client lacks `Accept-Encoding: gzip` (spec §3).
- No `SELECT *` on list endpoints (spec §3.1).
- All server tests: `cd server && pnpm test` (needs dev Postgres: `docker compose -f docker-compose.dev.yml up -d` from repo root). All CLI tests: `cd cli && cargo test`.
- Session cookie: `__Host-session`, HttpOnly, Secure, SameSite=Lax, HMAC-signed (spec §2.2, §4.1).
- Every state-changing `/api` request authenticated via session cookie must carry an `Origin` header equal to the configured `URL` origin, else 403. Bearer-authenticated requests are exempt (spec §2.2).
- ACL failure on viewer/artifact routes returns 404, never 403 (spec §2.3).
- Commit after each task with a conventional message ending in `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- UI copy: the editor role is always labelled "can update", never "can edit" (spec §12.1).

**upsertUserFromClaims logic (spec §4.1, §4.2 admin bootstrap, §4.3):** reject unless `email_verified === true`; if `iss` contains `accounts.google.com` → require `hd` claim present, use it as the domain (reject personal accounts with `AuthError('missing-hd')`); otherwise domain = lowercased email domain.
