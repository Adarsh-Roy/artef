# MCP OAuth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An MCP client (Claude Code, claude.ai) connects to `/mcp` with only a URL; the harness discovers the OAuth endpoints from a 401, opens the browser, the user approves on a page that reuses the existing SSO session, and the harness holds and refreshes its own token. The CLI drops out of MCP provisioning, and no bearer token lands in `~/.claude.json`.

**Architecture:** OAuth 2.1 authorization-code + PKCE (S256, public clients, no secrets), implemented by hand on the patterns `routes/cliauth.ts` already proved: one-time hashed codes spent by `DELETE…RETURNING`, session-only approval pages, origin-checked POST, refusal pages that never redirect to an unvalidated URI. Access tokens ARE existing `machine_tokens` rows (spec §7.0: "no new auth machinery") with a 7-day expiry; refresh tokens rotate and cascade-die when the user revokes the visible access token. Discovery per MCP spec: RFC 9728 protected-resource metadata, RFC 8414 AS metadata, RFC 7591 dynamic client registration, `WWW-Authenticate` on `/mcp` 401s only.

**Spec:** `artef-spec.md` §7.0 (reserves exactly this), §7.2 (cliauth patterns), §2.2 (origin checks). MCP authorization spec 2025-06-18.

## Global Constraints

- Access tokens are `art_live_…` machine tokens — same storage (hash-only), same bearer middleware, same revocation via `DELETE /api/tokens/:id`. No parallel token system.
- Invalid `client_id` or `redirect_uri` gets a 400 page, NEVER a redirect (open-redirect rule).
- Every distinct HMAC/secret use keeps domain separation; here we only hash (sha256) codes and tokens, mirroring cliauth.
- Chromium enforces `form-action` on the *redirect target* of a form POST (field lesson, docs/HANDOFF.md): the approve POST 302s to the client's `redirect_uri`, so the OAuth pages' CSP must allow `https:` plus loopback in `form-action`.
- The invariant test's route snapshot will fail; updating it deliberately is part of the work, and the new routes must be byte-route-free (no CSP sandbox implications).

### Task 1: Schema + migration

**Files:** Modify `server/src/db/schema.ts`; generate `server/drizzle/0004_*.sql` via `pnpm db:generate`.

Three tables:

```ts
/** Public OAuth clients (RFC 7591 dynamic registration). No secret is stored
 *  because none exists: PKCE is what binds the code to the client instance. */
export const oauthClients = pgTable('oauth_clients', {
  id: uuid('id').primaryKey().default(sql`gen_random_uuid()`),
  name: text('name'),
  redirectUris: text('redirect_uris').array().notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, precision: 3 }).notNull().defaultNow(),
})

/** One-time authorization codes, hashed like cli_auth_codes. Unlike those, the
 *  token is NOT pre-minted: PKCE must pass first, so minting happens at the
 *  exchange inside the same transaction that spends the code. */
export const oauthCodes = pgTable('oauth_codes', {
  codeHash: bytea('code_hash').primaryKey(),
  clientId: uuid('client_id').notNull().references(() => oauthClients.id, { onDelete: 'cascade' }),
  userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  workspaceId: uuid('workspace_id').notNull().references(() => workspaces.id, { onDelete: 'cascade' }),
  redirectUri: text('redirect_uri').notNull(),
  codeChallenge: text('code_challenge').notNull(),
  expiresAt: timestamp('expires_at', { withTimezone: true, precision: 3 }).notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, precision: 3 }).notNull().defaultNow(),
})

/** Rotating refresh tokens. `accessTokenId` cascade means revoking the visible
 *  machine token in the token list fully disconnects the client — its next
 *  refresh finds no row and it must re-run the browser flow. */
export const oauthRefreshTokens = pgTable('oauth_refresh_tokens', {
  tokenHash: bytea('token_hash').primaryKey(),
  clientId: uuid('client_id').notNull().references(() => oauthClients.id, { onDelete: 'cascade' }),
  userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  workspaceId: uuid('workspace_id').notNull().references(() => workspaces.id, { onDelete: 'cascade' }),
  name: text('name').notNull(),
  accessTokenId: uuid('access_token_id').notNull().references(() => machineTokens.id, { onDelete: 'cascade' }),
  expiresAt: timestamp('expires_at', { withTimezone: true, precision: 3 }).notNull(),
  createdAt: timestamp('created_at', { withTimezone: true, precision: 3 }).notNull().defaultNow(),
})
```

### Task 2: `server/src/routes/oauth.ts` — the whole flow

Constants: `CODE_TTL_MS = 60_000`, `ACCESS_TTL_MS = 7d`, `REFRESH_TTL_MS = 90d`,
`REFRESH_PREFIX = 'art_refresh_'`, verifier charset per RFC 7636 (`/^[A-Za-z0-9._~-]{43,128}$/`),
challenge `/^[A-Za-z0-9_-]{43}$/`.

Routes (all registered by `registerOauthRoutes(app, deps)`):

- `GET /.well-known/oauth-protected-resource/mcp` and `…/oauth-protected-resource`:
  `{ resource: cfg.url + '/mcp', authorization_servers: [cfg.url], bearer_methods_supported: ['header'] }`.
- `GET /.well-known/oauth-authorization-server`: RFC 8414 —
  issuer `cfg.url`, authorization/token/registration endpoints, `response_types_supported: ['code']`,
  `grant_types_supported: ['authorization_code','refresh_token']`,
  `code_challenge_methods_supported: ['S256']`, `token_endpoint_auth_methods_supported: ['none']`.
- `POST /oauth/register` (unauthenticated, JSON): `redirect_uris` required, each an absolute
  `https:` URL or loopback `http:` (`localhost`/`127.0.0.1`, any port, any path). `client_name`
  ≤200 chars kept. 201 with `{client_id, redirect_uris, client_name?, token_endpoint_auth_method:'none', grant_types, response_types}`.
- `GET /oauth/authorize` (browser): no session → `/auth/login?next=…` (cliauth's `toLogin`).
  Unknown `client_id` or non-matching `redirect_uri` → 400 refusal page, no redirect.
  Bad/missing `response_type`/`code_challenge`/`code_challenge_method` → 302 to redirect_uri
  `?error=invalid_request&state=…`. Valid → consent page naming the client and the account,
  form POSTs everything to `/oauth/authorize/approve` with an Authorize and a Deny button.
- `POST /oauth/authorize/approve` (session-only + `originCheck`, mirroring cliauth): re-validate
  all fields from the form; Deny → `?error=access_denied&state=…`; Approve → mint 24-byte
  base64url code, sweep expired rows, insert `oauth_codes`, 302 to
  `redirect_uri?code=…&state=…`.
- `POST /oauth/token` (unauthenticated, form-encoded):
  - `authorization_code`: spend code via transactional `DELETE…RETURNING` on hash + unexpired;
    verify `client_id` and `redirect_uri` equal the row's; PKCE: `b64url(sha256(verifier)) ===
    challenge` via `timingSafeEqualBuf`. All failures → `{error:'invalid_grant'}` 400 (one
    answer). Success (same tx): insert machine token (name `mcp: <client_name|client_id-prefix>`,
    `expiresAt` now+7d), insert refresh row, return
    `{access_token, token_type:'Bearer', expires_in, refresh_token}` with `Cache-Control: no-store`.
  - `refresh_token`: spend refresh row via `DELETE…RETURNING` (hash + unexpired + client_id
    match); delete the old machine-token row by `accessTokenId` in the same tx; mint new access
    + new refresh (rotation), same response shape.
  - Anything else → `{error:'unsupported_grant_type'}`; malformed → `{error:'invalid_request'}`.

Pages copy cliauth's minimal `page()` style; headers from a new `oauthPageHeaders()`.

### Task 3: headers, 401 challenge, wiring

- `lib/headers.ts`: `OAUTH_CSP = "default-src 'none'; style-src 'unsafe-inline'; form-action 'self' https: http://localhost:* http://127.0.0.1:*; base-uri 'none'; frame-ancestors 'none'"` + `oauthPageHeaders()` (nosniff, same-origin referrer, no-store) with a comment tying `form-action` to the approve-redirect lesson.
- `auth/bearer.ts`: both 401s gain `WWW-Authenticate: Bearer resource_metadata="<cfg.url>/.well-known/oauth-protected-resource/mcp"` **only when `c.req.path` is `/mcp`** — the API's 401 shape stays untouched.
- `routes/mcp.ts`: the route's own no-bearer 401 gains the same header.
- `app.ts`: `registerOauthRoutes(app, deps)` next to `registerCliAuthRoutes` (same family, same comment style).

### Task 4: Tests (`server/test/oauth.test.ts`) then the suite
